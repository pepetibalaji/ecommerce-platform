# Current Implementation

Notification Service owns PostgreSQL notifications, recipients, preferences, deliveries, and processed Kafka-event records. It consumes order/payment/inventory and user-contact events; `ProcessedEvent` provides idempotent handling. `NotificationEventService` creates notification work, `RecipientDirectoryService` resolves contact data, and `NotificationDeliveryService` invokes configured Logging, Mailtrap, or SMTP providers with delivery state. API routes under `/api/v1/notifications` read user notifications and preferences; admin routes expose failed notifications and delivery histories. Runtime dependencies are PostgreSQL, Kafka, OAuth/JWK, email provider settings, Config Server, metrics, tracing, and actuator. Operations monitor consumer lag, delivery retry/exhaustion, and provider availability while avoiding recipient data and credentials in logs.
