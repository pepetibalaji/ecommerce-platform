# Product Service data model

The standard deployment owns `product_db.products` and `product_db.product_outbox`. Other services must not write these collections. MongoDB must support transactions (replica set or sharded cluster).

## Products

| Field | Representation and contract |
| --- | --- |
| `_id` / `id` | UUID stored as string; generated by Product and protected by Mongo's unique primary index. |
| `sellerId` | UUID of the eligible owner. Admin creation verifies supplied ownership; seller routes derive identity from JWT. |
| `version` | Spring Data optimistic revision. New records start at zero; published lifecycle productVersion is revision + 1. Not a browser-editable field. |
| `active` | Boolean default true. Legacy missing/null values are treated as true; false hides public list/detail/facets. |
| `name` | Required nonblank text, trimmed, at most 200 characters. |
| `description` | Optional plain text, at most 10,000 characters; rendered escaped by clients. |
| `category`, `brand` | Optional trimmed labels, at most 100 characters; blank values become null. |
| `price` | Positive BSON Decimal128; new/update requests allow at most 18 integer digits and four decimal places without rounding. |
| `currency` | Uppercase supported monetary ISO 4217 code. Omitted request currency defaults to USD. Startup backfills legacy missing/null stored currency to USD. |
| `imageUrls` | Up to ten approved HTTPS references. Null/missing list is returned as an empty array. |
| `createdAt`, `updatedAt` | BSON dates mapped to UTC Instant and serialized with Z. Existing BSON dates retain their stored instant. |

Startup initializes missing/null legacy product revisions to zero before normal mutations. Coordinate rollout so old writers cannot replace upgraded documents without revision fields. Currency backfill is a compatibility assumption, not exchange-rate conversion; review historical currency provenance before production rollout.

DELETE archives by setting active=false and retains the document. Products contain no inventory counters or immutable purchase snapshots; Order retains purchase history.

## Transactional outbox

| Field | Purpose |
| --- | --- |
| `_id` / `id` | UUID event identity; preserved across retries. Existing UUID storage configuration must remain compatible. |
| `productId`, `sellerId`, `type`, `occurredAt` | Routing, ownership, audit type and UTC occurrence time. |
| `payload` | Immutable ProductLifecycleEvent snapshot: schema/product versions, current catalogue state and acting user when available. |
| `status` | PENDING, PROCESSING, PUBLISHED or DEAD. |
| `attempts`, `nextAttemptAt` | Retry count and next eligible delivery time. |
| `leaseToken`, `leaseUntil` | Unique claim ownership and expiry; completion writes require the exact token. |
| `publishedAt`, `lastError` | Delivery time and safe failure classification. |

A product mutation and its event record commit or roll back together. Existing payloadless records are repaired as current reconciliation snapshots during delivery. Published/dead rows are retained; no automatic destructive retention is configured.

## Indexes

| Index | Fields / use |
| --- | --- |
| Mongo primary | Unique product `_id` and outbox `_id`. |
| `seller_id_idx` | Seller catalogue lookup (annotation-driven). |
| `category_idx`, `price_idx`, `category_price_idx` | Existing direct/internal category and numeric price lookups. |
| `public_catalogue_filters_idx` | Existing active/category/brand/price compound filter index. |
| `catalogue_newest_idx` | active, createdAt descending, ID ascending. |
| `catalogue_price_idx` | active, price ascending, ID ascending. |
| `catalogue_name_idx` | active, name ascending, ID ascending. |
| `catalogue_category_price_idx` | category, active, price, ID. |
| `catalogue_brand_price_idx` | brand, active, price, ID. |
| Revision index | version, initialized with legacy revision migration. |
| `outbox_delivery_idx` | status, nextAttemptAt, leaseUntil, occurredAt. |

The catalogue indexes use the same case-insensitive English secondary collation as category/brand equality and name sorting. Substring matching and computed relevance still evaluate selected candidates; the indexes do not provide a full-text engine.

See [API](api.md) for validation, query performance limits and serialization, and [lifecycle operations](lifecycle-operations.md) for rollout/recovery.
