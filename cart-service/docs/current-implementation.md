# Current Implementation

Cart Service is a Redis-backed, JWT-protected cart boundary. `CartController` exposes `POST /api/v1/cart`, `PUT /api/v1/cart/{itemId}`, `GET /api/v1/cart`, `DELETE /api/v1/cart/{itemId}`, and `DELETE /api/v1/cart` for the authenticated user. It also exposes guest-cart creation, read, item mutation, deletion, and `/merge-guest` under the same base path. `CartService` scopes persisted `Cart`/`CartItem` data to the caller user ID or guest token through `CartRedisRepository`. Cart stores product ID and quantity only; it neither verifies product existence nor stores authoritative prices. Checkout must create an Order, which resolves the product and price from Product Service. Required runtime dependencies are Redis, OAuth/JWK configuration, Config Server (optional locally), actuator, tracing, and Prometheus.
